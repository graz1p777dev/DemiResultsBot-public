# Проверка качества общения — 24.10.2026

Здесь только вымышленные диалоги, не экспорт клиентской БД и не копия чата владельца с ключами.

`cases.json` содержит 18 отдельных ситуаций и два последовательных разговора по четыре реплики: 26 проверяемых шагов. Для разговоров история действительно продолжается предыдущими ответами модели. Четыре завершающие реплики обрабатываются детерминированно без AI; остальные проверяют генератор и контролёр качества. `summary_cases.json` — два отдельных живых теста резюме-гипервизора.

Во всех живых текстовых проверках использован действующий DeepSeek fallback, а не успешный OpenAI text-вызов. Платный OpenAI ASR — отдельная интеграция, описанная в VERIFICATION_20261024.md. Промпт/память прочитаны из разрешённого runtime; в архив включены только их SHA256, не содержимое.

Проверки эвристические, результаты модели недетерминированы. Ручной просмотр дополняет правила, а не заменяется зелёным счётчиком. В кыргызском диалоге может встречаться избыточное уточнение уже описанного ухода; оценка носителем языка и большая выборка ещё нужны. Этот набор не доказывает идеальное общение со всеми людьми, фактическую запись или клиентскую доставку.

## Воспроизведение

Offline без ключей и без внешней сети:

```sh
PYTHONPATH=backend .venv/bin/python -m pytest backend/tests -q
```

Live eval выполняется только внутри разрешённого backend runtime, где уже защищённо настроены доступ к БД и модели. Это отдельный запуск, не pytest/build. Скрипт читает только бизнес-settings в read-only транзакции, не извлекает клиентскую историю и не вызывает отправки или создание заявок.

```sh
PYTHONPATH=backend python scripts/eval_prompt_quality.py \
  --allow-live-ai --suite qa/prompt-quality/cases.json --output /tmp/quality-new-run.json
PYTHONPATH=backend python scripts/eval_prompt_quality.py \
  --allow-live-ai --suite qa/prompt-quality/summary_cases.json --output /tmp/summary-new-run.json
```

Нужны явное разрешение на платные AI-вызовы и новый output path; старые результаты не перезаписываются. `--candidate-prompt` принимает приватный staged JSON (`after`), который нельзя публиковать. Перед публикацией заново проверить даже автоматически обезличенный output: URL/номера скрываются, похожие на credentials ответы блокируют архив.

## Значение «гипервизор»

В коде `summarize_dialogue` — краткое резюме для менеджера, usage purpose `hypervisor`. `verify_reply` — отдельный контролёр черновика. Ни тот, ни другой не имеет права отправлять ответ вместо сотрудника. Отдельного автономного управляющего агента с названием Hypervisor здесь нет.

Сервер — KVM-гость. Доступные проверки подтверждают состояние гостевой ОС/приложения, а не исправность физического гипервизора провайдера.
