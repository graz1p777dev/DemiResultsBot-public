# Голосовые: исправление 23.10.2026

## Причина и live-проверка

В проблемной заявке расшифровка отсутствовала. Исходное аудио было доступно: без авторизации хранилище Green возвращало HTTP 200, audio/ogg. Старый загрузчик добавлял amoCRM Bearer token к чужому media host и получал HTTP 400. После корректной загрузки OpenAI transcription отдельно возвращал **429 credit_balance_exhausted**. Текстовый DeepSeek fallback не является распознаванием аудио.

Дополнительно summarizer и несколько вспомогательных AI-запросов сериализовали `[voice] URL` без нормализации. При длинном URL ограничение длины могло отрезать расположенную после него расшифровку. Старый helper снимал только первый маркер в начале сообщения, не префиксы истории и несколько голосовых.

## Выложено на production

- amoCRM Authorization отправляется только HTTPS-хостам amoCRM, не хранилищу Green.
- Все голосовые маркеры удаляются из AI input, сохраняя текст и подписи говорящего. Нормализация выполнена до truncation в summary/translation и при serializing extraction/analysis.
- Если последнее сообщение содержит нераспознанное голосовое, генератор не создаёт клиентский ответ «напишите текстом»: исключение идёт в существующий manual-approval path с пустым ответом. Это не отказ от сохранения аудио.
- Ошибка распознавания отмечается в raw metadata; логируется только тип ошибки, без URL/ключа/содержимого.
- Сообщённая владельцем pending-карточка переведена в ручное прослушивание, исходное аудио сохранено, Telegram-карточка обновлена. Перед изменением проверены pending/no manager edit, сохранён защищённый backup. WhatsApp отправок не добавлено.

Заменены только `backend/app/services/openai_service.py` и `backend/app/api/admin.py`. Перед deployment сверены hashes и env трёх сервисов, сохранены предыдущие образы/файлы. Новые backend/worker/beat images построены поверх соответствующих текущих production images. Более новая production-версия pipeline сохранена без замены snapshot-версией. БД schema не менялась, миграция уже находилась на head. CRM frontend/Samat и соседние сервисы не менялись.

После deployment проверены health/backend, login CRM HTTP 200, hashes во всех трёх контейнерах. Повтор исходного аудио через исправленный `transcribe_voice` больше не даёт download HTTP 400: доходит до transcription API и получает подтверждённый quota 429.

## Что НЕ исправлено / не включено

**Полноценное автоматическое распознавание сейчас не работает из-за недоступного paid ASR.** Пополнение/замена сервиса распознавания требует владельца и отдельного живого retest, в том числе кыргызского. Не представлять этот релиз как готовую поддержку всех голосовых.

В изолированных QA-контейнерах проверены локальные Whisper и кыргызская Vosk-модель. Полученные результаты были недостаточно достоверными; в production эти модели/зависимости не подключены, сомнительный текст в CRM/черновик не записан. Собственные временные model/dependency downloads удалены, восстановлено около 2 ГБ свободного места. Их можно повторно получить из публичных источников; пользовательские данные/backup не удалялись.

Проверки исходной локальной копии: **179 backend tests + 16 subtests**. Интеграция с более новой локальной continuation-веткой: **194 passed + 16 subtests**; её дополнительные diagnostics/outbox/Telegram tests сохранены. Включены normalization/payload regression, scope Authorization и incoming voice failure → сохранённое вложение → одна manual approval → ноль клиентских sends. Дополнительно проверены multiline transcript и failed voice перед typed greeting в одном буфере. Провайдеры в этих тестах mocked. Реальная live-проверка подтверждает download и внешний quota blocker, а не успешное распознавание.

Исходные номера, Telegram IDs, lead/message IDs, signed media URLs, содержимое аудио и private backup locations не включаются в публичный отчёт.
