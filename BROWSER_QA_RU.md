# Браузерное продолжение без OpenAI

Проверка 22.10.2026. Использована отдельная копия текущего полного CRM source,
Next development server и настоящий Google Chrome через Playwright. Вход проходит
через отдельные Supabase Auth/PostgREST и новую QA-базу. Авторизация не mocked.
Production env, клиенты, переписки и ключи транспорта в QA не передавались.
Новых вызовов OpenAI не выполнялось.

## Подтверждённые сценарии

| Сценарий | Наблюдение |
|---|---|
| Владелец | Вход паролем, dashboard |
| Сотрудник | Пароль → выбор аккаунта → мини-пароль → dashboard |
| Сотрудники | Создание через форму, изменение имени; результат после reload и в БД |
| Увольнение | Синтетический сотрудник появился в архиве; восстановлен и снова active |
| Консультация | Создание, изменение, повторное открытие и удаление владельцем; soft-delete подтверждён в БД |
| Own scope | Чужая консультация отсутствовала в списке сотрудника |
| Финансовые права | Сотрудник без finances.view получил «Нет доступа» |
| Изменение роли | Попытка создания сотрудником получила «Недостаточно прав»; новой роли в БД нет |
| Мобильная ширина | Консультация видна при viewport 390 × 844; это не полный mobile audit |
| Расход | Категория и расход созданы через форму, 123 сома подтверждены после повторного открытия |
| Изменение расхода | Через форму изменён на 246; UI, amount_original и amount_som подтверждены после повторного открытия и чтением QA-БД |
| Удаление расхода/категории | Удалены через UI, итог 0; оба soft-delete подтверждены чтением QA-БД |

## Важные ограничения стенда

Совпадение колонок не гарантирует одинаковую схему. У существующего тестового
стенда были все 1105 production-колонок и ещё 448 дополнительных; некоторые RPC
отличались от production. Для финансовой проверки в новой QA-базе сверены и
перенесены ровно 10 текущих определений функций вместе с зависимостями:
`save_expense`, `delete_expense`, `save_expense_category`,
`delete_expense_category`, `get_unlinked_inventory_sales_daily`,
`_assert_actor_active`, `_assert_finances_editor`, `_assert_finances_manager`,
`_finances_edit_ok`, `_finances_manage_ok`.

В QA добавлены синтетическая компания, membership, роли и финансовые права
владельца. Проверки доступа и авторизация не отключались. Первоначальные ошибки
пустых fixtures и сбросы соединений собственного QA-прокси устранены в стенде;
их нельзя выдавать за найденные и исправленные ошибки production.

Это ограниченный browser E2E, а не доказательство всех CRM-сценариев. Не закрыты
полная матрица ролей/отделов, чужой объект по прямому ID, все сделки/записи,
расчёт/закрытие зарплат, отпуск/табель, долги/инвесторы/распределение и перенос
полной схемы миграциями с нуля. Снимок публичной CRM отличается от проверенного
текущего полного source. Production CRM в этом продолжении не менялась.

## Остальные реальные gates

- 16 старых `send_failed` дополнительно проверены чтением backend: у всех пустой
  raw_payload, нет outbox/provider IDs. Исход доставки не установлен; записи не
  менялись и отправки не повторялись.
- Для живых Telegram кнопок, WhatsApp/Instagram и исходящих media нужен текущий
  согласившийся тестовый контакт по AGENTS.md. Старый номер не переиспользуется.
- Ночная read-only проверка назначена на 23.10.2026 после 10:00 Asia/Bishkek;
  на момент этого отчёта полная ночь ещё не наблюдалась.
- Расширение root filesystem требует администратора: обычному пользователю
  `sudo -n` недоступен. Диск/разделы/LVM не менялись, см. CAPACITY_RU.md.
- Автономная консультация всем клиентам не включалась. Без OpenAI можно продолжать
  проверенный текстовый путь, но это не заменяет согласование действующих
  бизнес-правил, источников цен/наличия, записи и эскалации.
