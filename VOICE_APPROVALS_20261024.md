# Голосовые и простое согласование — 24.10.2026

## Установленные изменения

- Проверен ключ OpenAI, ранее переданный владельцем: он отличается от старого активного ключа. Авторизация успешна; исходное проблемное голосовое действительно распознано.
- ASR использует `gpt-transcribe`, JSON и автоопределение языка без принудительного `ky`: API отклонил такой language hint, но тот же файл без него распознался. Получено 223 символа, включая кыргызские буквы. Это проверка записи и интеграции, не всесторонний замер точности двух языков.
- Отдельные backend settings `OPENAI_ASR_API_KEY` и `OPENAI_ASR_MODEL` используются для WhatsApp, Telegram и CRM. Текстовый AI-ключ и существующий DeepSeek fallback не менялись. Ключи в git не включены.
- Telegram: только сообщение клиента, предложенный ответ, короткий статус и основные действия. Убраны контакт, score, lead ID, контекст, память, перевод, сохранение, заметки, консультация, этапы и вспомогательный AI-редактор.
- Основные действия: принять, отклонить, изменить вручную. Пустой purchase-черновик нельзя принять без настоящего ответа.
- Ссылка CRM ведёт в `/dashboard/dialogs?lead=<external-id>`; CRM точно разрешает внешний ID, в том числе за пределами загруженного списка. Для Green/Meta CRM-generated ID не выдаётся за настоящую amoCRM-сделку: неподтверждённая amoCRM-ссылка скрыта.

## Telegram: новая правка

1. Ответить на карточку текстом — это готовый заменяющий ответ. Или нажать «Изменить вручную» и ответить на открывшуюся подсказку.
2. Ответить голосовым — это инструкция, как ИИ должен изменить ответ. Сначала выполняется ASR, затем AI-редактирование.
3. Бот показывает отдельный предпросмотр, ссылки на исходную карточку и голосовую инструкцию. Длинный текст показывается несколькими частями, без скрытой отправляемой концовки.
4. «Принять и отправить» применяет и отправляет именно этот текст. «Отклонить правку» оставляет исходный черновик без изменений.

Предпросмотр привязан к сотруднику и чату, живёт 30 минут, одноразово потребляется. Snapshot CAS защищает от поздней правки и параллельного подтверждения. До явного решения клиенту ничего не отправляется. Ошибка распознавания не превращается в выдуманный ответ.

В приватных чатах переход по `tg://openmessage` зависит от Telegram-клиента. Встроенная reply-ссылка предпросмотра также ведёт к исходной инструкции; реальную навигацию на телефоне ещё надо проверить. Для групп используется стандартная ссылка `t.me/c`.

## CRM

В диалоге сохранены генерация ответа, ручная правка и голосовой ввод. Голосовая AI-инструкция создаёт предложение через новые endpoints:

```text
POST /admin/approvals/{id}/edit-preview
  {reply, prompt?, expected_current?}
  → {proposal_token, edited_reply}
POST /admin/approvals/{id}/edit-preview/{token}/accept
POST /admin/approvals/{id}/edit-preview/{token}/discard
```

Предпросмотр не перезаписывает pending-ответ. Отказ от правки не равен отклонению всей карточки. Смена текста инвалидирует прежнее предложение. `expected_current` обнаруживает устаревший экран до подготовки предложения; snapshot проверяется повторно при применении. Прокси сохраняет те же STAFF/approvals-edit и ограничения доступа к конкретной записи.

Запись голосового клиенту сначала останавливается для локального прослушивания, затем отправляется отдельным действием. Карточки без AI-текста также видны в CRM для ручной обработки.
